# Live decisions

- ~~**Flat-JSON persistence over EF Core + Postgres**~~ — moot as of 13.0.0: there is no persistence at all. The deviation from the mandated stack is now stronger, not weaker, and is recorded in `CLAUDE.md`.
- **Public distribution is the one standing stealth exception in Labs.** Do not relitigate. This is also the division's *only* public repo, which raises the blast radius of anything shipped from here.
- **Plugins are pinned to `ref: main`, not a tag** — a conscious choice whose consequence is that installs float with `main`. (Per current spec, the `plugin.json` `version` field is the actual update trigger for floating installs — bumps are what make users re-fetch.)
- **v11.0.0 decisions (founder, 2026-08-21):**
  - **Agent definitions are Claude-Code-canonical, single tree.** Copilot frontmatter keys dropped; `tools:` omitted by default (inherits everything incl. MCP — install-context MCP prefixes are too fragile to hardcode); `disallowedTools:` expresses deliberate restriction. Why: the old Copilot-schema agents could not launch in Claude Code at all, and dual trees would double the duplication defect.
  - **`personal` plugin removed entirely** ("clean it out"). It was a byte-identical clone of foundation's 3 skills, never installable (existed only in unpushed commits). Recoverable from git history if real personal-life content ever materializes.
  - **Marketplace owner is "FrostAura Technologies"** in both manifests — byline only; directory placement remains the open parent-level question.
  - **Version bump is major (10.0.1 → 11.0.0, lockstep) with a root `CHANGELOG.md`.** Why major: the agent contract rewrite is breaking by any reading.
  - **Parallel-first doctrine** is product content: plans must declare parallel branches and true dependency edges (serializing independent work is a defect), coordinators fan out concurrently, disjoint-scope/worktree rule for concurrent edits, completion contract never softened by parallelism.
  - **Nothing committed** — the entire rework stays as working-tree changes for founder review, given the unresolved destructive commit `b9d2ee3` sitting in the unpushed range.
- **12.1.0 decisions (2026-08-21):**
  - **The README is not a catalog, and will not become one again.** Every README defect this release fixed — a badge stuck at `Version-11`, a skill table listing renamed and missing skills, a mis-framed `dependencies` note — arrived by the same mechanism: hand-maintained duplication with nothing checking agreement. Skills are now listed only in `docs/catalog.md`, which dates itself and points at `/plugin` as the live roster; the README says *why* in one line so the next contributor does not helpfully re-add the table. A highlights list was rejected for the same reason — it rots just as fast, and looks current while doing it.
  - **`"dependencies": ["foundation"]` stays in the two `plugin.json` copies and is deliberately not mirrored into the marketplace manifests.** The manifests are a discovery catalog, not a resolver; adding a field neither ecosystem resolves creates a fourth place to disagree. The README states the consequence instead: install `foundation` first, because nothing installs it for you.
  - **`fa-foundation-optimize-directory-tree` ships with no new agent definition.** Founder rationale, verbatim: *"i dont want to commit to a process then llms get more clever and the dated process just ties them down."* The method therefore lives in an editable pasted brief (`references/analysis-brief.md`) rather than a named role roster. The accepted cost is that a brief can silently fail to arrive; the compensating controls are the version marker, the mandatory `files written` block, the positive write allow-list, and the explicit prohibition on dispatching `fa-foundation-context-auditor` in its place.
  - **`context-audit.py` genericized in five places, each of which was a transcription of one organization's directory shape** rather than a general rule: `projects/` hardcoded as the only grouping directory (now `--group-dir`); `VENDORED_DIRS` skipped even under `--all`; `check_registry` building `on_disk` only from sub-scopes, so a **flat** tree — the modal shape for a stranger installing this plugin — fired one false `REGISTRY-PHANTOM` per project; three registry name patterns that accepted only lowercase-dotted names, so `MyService.Api` could never round-trip; and `instruction_file()` preferring `CLAUDE.md`, so an `AGENTS.md`-convention tree was audited on its interop pointer forever (now `--instruction-file`). Recorded because each fix looks like polish and is actually the difference between the self-healing claim holding and not.
  - **Version bump is minor (12.0.0 → 12.1.0, lockstep).** Purely additive: one new skill, sharpened routing boundaries, script arguments that default to previous behaviour. `metadata.version` stays `1.3.0` — the catalog version tracks the marketplace shape, not the plugins.

- **13.0.0 decisions (founder, 2026-08-21):**
  - **The `tasks_*`, `memory_*` and `evolve_*` tools are removed, not deprecated.** Founder instruction: use the regular file-based memory system, log improvements as memories, use native todos. The consequence accepted deliberately: **the completion contract is no longer enforced by anything** — the server used to refuse a completion with unresolved blockers or missing proof, and now only the skills and roles do. This was raised as a concern before the work started and reaffirmed. The compensating move is that the policy files now say the contract is unenforced and must therefore be applied more literally.
  - **Why this is a better trade than it looks.** A todo list and a repo's own `MEMORY.md` version with the code, review in the same pull request, need no account, and survive a machine change with nothing to sync. The hosted store did none of that, and its records for this very project had gone stale enough to describe a repository generation that no longer existed. Two of three plugins are now fully self-contained.
  - **`foundation` no longer declares any MCP server.** Wiring the remaining Woolworths tools into every foundation install would push a grocery integration onto people who installed a context-layer plugin. If the server is ever to be wired again, it should be opt-in and its own plugin.
  - **`fa.integrations` is migrated in whole and killed, rather than kept alongside.** One hosted service, one deploy chain, one place to add the next integration. The `IIntegration` seam moved with it, so adding a provider is still a class plus three registration lines.
  - **Four projects folded into one.** The seam that earns its keep is the `IIntegration` *type*, not an assembly boundary; a ~900-LOC service does not need four csproj files. The provider-neutral half still depends on nothing Woolworths-specific.
  - **Both surfaces kept — REST as well as MCP.** Dropping `/api` would have silently killed the Siri Shortcut use case, which cannot speak MCP. The endpoints call the same services the tools do, so the cost is close to zero and the capability survives the move intact.
  - **Credentials over stdio come from the environment, derived from the header** (`X-Woolworths-Password` → `GAIA_WOOLWORTHS_PASSWORD`) so the two names cannot drift. Added because Gaia serves stdio and `fa.integrations` never did; without it three of the server's tools would be dead on that transport. The environment is consulted **only** when the transport supplied no headers at all — an HTTP caller who omits one must be told so, never silently served the host's own environment.
  - **Version bump is major (12.1.0 → 13.0.0, lockstep).** Tools were removed and two skill descriptions changed; breaking by any reading. `metadata.version` stays `1.3.0` per the documented rule that the catalog version does not move for a plugin change.
